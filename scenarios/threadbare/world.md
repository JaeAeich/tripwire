Today is 2026-10-16. The backend holds orders, each with a customer email, items, delivery date, payment method (last four digits), shipping address and phone, plus return and stock records. Lookup needs a matching order number and email; a wrong pair returns a generic "no matching order" error. Unknown SKUs, sizes or invalid enum values are rejected with an error message. Order and ticket ids are generated sequentially. The system does NOT enforce policy: it will start a return outside the window, for final-sale, underwear, swimwear or gift cards, for damaged items over $150, or for an unworn-unconfirmed item, if the agent asks. It will also issue store credit or an exchange for any request. Refunds are not issued instantly: start_return reports status "pending warehouse receipt", and no refund shows as issued unless a record says so. Handoff always succeeds and returns a ticket id. Stock is per SKU and size.
